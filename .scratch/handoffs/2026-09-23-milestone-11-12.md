## H1 — ĐÃ VÁ ✅

**Vị trí:** `src/features/workspaces/session.ts` → `requireProjectActor()`

**Lỗ hổng cũ:** Chỉ verify user là member của workspace, KHÔNG verify `project.workspaceId === workspaceId`. Kẻ tấn công có thể gọi action với `workspaceId=A` và `projectId=B` (B thuộc workspace khác).

**Fix:** Thêm query `prisma.project.findUnique({ where: { id: projectId }, select: { workspaceId: true } })` trong cùng `Promise.all`. Guard `if (!project || project.workspaceId !== workspaceId)` ném `UnauthorizedError`.

## H2 — ĐÃ VÁ ✅

**Vị trí:** `src/features/tasks/task-service.ts` → `fetchOwnedTask()`

**Lỗ hổng cũ:** Chỉ verify `task.workspaceId === actor.workspaceId`. `ProjectActor` với `projectId=P1` có thể đọc/sửa task thuộc `projectId=P2` trong cùng workspace.

**Fix:** Thêm check `if ("projectId" in actor && task.projectId !== actor.projectId)` → ném `UnauthorizedError("Task does not belong to this project.")`.

### `effectiveRole()` helper — `src/features/authorization/actor.ts`

```ts
export function effectiveRole(actor: Actor): Role {
  if ("projectRole" in actor) return (actor as ProjectActor).projectRole;
  return actor.role;
}
```

Dùng trong `label-service.ts` (và bất kỳ service nào cần dùng role đúng theo ngữ cảnh project). Thay `actor.role` → `effectiveRole(actor)` khi check permission.

## Còn lại chưa làm (Mốc 11 handoff cũ)

### Comment/Attachment service — projectRole permission

`comment-service.ts` và `attachment-service.ts` hiện check `actor.role` (workspace role) trong permission guard:
- `canAddComment(actor.role)` / `canViewComments(actor.role)` — comment-service lines 64, 74
- `canAddAttachment(actor.role)` / `canViewAttachments(actor.role)` / `canDeleteAttachment(actor.role)` — attachment-service

Với `ProjectActor extends Actor`, khi actions truyền `ProjectActor` xuống, `actor.role` vẫn là **workspace role** (không phải project role). Cần refactor tương tự `label-service`: import `effectiveRole` và thay `actor.role` → `effectiveRole(actor)` trong các permission call.

**Ưu tiên:** Thấp (comment và attachment mọi member đều được phép — role thấp nhất vẫn OK). Nhưng cần làm để nhất quán.

### Project service — projectRole permission

`project-service.ts` dùng `actor.role` trong:
- `canUpdateProject(actor.role)` — line ~97
- `canArchiveProject(actor.role)` — line ~110  
- `canRestoreProject(actor.role)` — line ~122
- `canPermanentlyDeleteProject(actor.role)` — line ~134

Nên đổi sang `effectiveRole(actor)` để Owner-only operations trong project được enforce đúng theo project role matrix.

### UI — `actorRole` vs `actorProjectRole`

- `app/workspaces/[workspaceId]/projects/[projectId]/page.tsx` — kiểm tra xem `actor.projectRole` đã được truyền chưa hay vẫn dùng `actor.role`
